Why 256 MiB?

This is an application policy, not an IFC format or Rust language limit. The guard refuses files at or above 268,435,456 bytes before parsing. The project requires bounded inputs and the IFC path reads the complete file into memory. No rationale for exactly 256 MiB was found.

In inspected release and source, open/recovery and autosave enforce the cap; ordinary native save has no corresponding size check. A project saved over the threshold may not reopen. Source finding, not reproduced by generating an oversized native file in this audit.
