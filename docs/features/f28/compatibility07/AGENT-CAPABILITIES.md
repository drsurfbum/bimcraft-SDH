# Agent capability gate — F28-C / 0.7

This matrix separates implemented UI/domain behavior from registered and transport-tested agent behavior. No MCP exception is granted. Generic element/property access is not a substitute for documentation operations; protected-record guards must continue refusing raw writes to those records.

`tests/features/f28/mcp-coverage.py` initializes the real source stdio server, discovers its actual schemas and makes lifecycle/read/edit/invalid-input/wrong-document/allowed-root/read-only calls. It verifies the exact loaded fork files and reports `AUDIT_COMPLETE_GAPS_OPEN`; this is audit success, not documentation acceptance. Foundation controls retain actual source and separately packaged stdio lifecycles, independent saved IFC validation and live host JSON-RPC calls. Direct UI helpers and imported functions are supplementary tests, not proof of MCP transport.

## MCP-01 contract compatibility

Reviewed cutoff `9224167fe3e2e856c57679065b545d834f52ade1` defines `materials_list`, `assemblies_list`, `material_create`, `material_edit`, `assembly_create`, `assembly_edit`, `assembly_duplicate`, dynamic `walls_add`, `walls_edit`, exact `walls_list`, and session-aware history. New edits require `documentId` and `expectedRevision`; headless adds explicit `doc`. `projectId` is persistent and not sufficient to identify an opened editor. Reuse that binding/revision contract for documentation catch-up after MCP-01 adoption. Those definitions are not present merely because this document names them, and the MCP-01 branch has not been imported. Its owner has independently advanced preparation; this candidate keeps its fixed approved foundation.

## Proposed separately owned bounded catch-up slice (not started here)

**DOC-MCP-01 — explicit documentation sources, records and vector outputs.** Assign a separate owner and PM-approved post-MCP-01 main pin. Extend the existing `agents.js`/headless router with one shared DOM-free documentation adapter; do not create another dispatcher or model store.

1. Read sources, effective/raw settings, dimension/reference status, full schedule/legend rows, sheet placements and diagnostics. Proposed semantic groups: `documentation_sources`, `documentation_settings`, `documentation_annotations`, `documentation_tables`, `documentation_sheets`, `documentation_export`; names are proposals, not registrations.
2. Add bounded writes through existing view/projected/drafting/dimension/sheet operations. Require editor session ID, expected revision, stable source/record IDs and raw-mm arguments. Refuse foreign/stale sources, unsupported versions, busy states and template-controlled writes before mutation. The target must never come from browser selection or display names.
3. Export an explicit supported source/continuation or drawing set using existing CSV/vector writers and current save/export permissions and allowed-root/overwrite policies. Live state operations may be live-only with an explicit headless explanation; record/composer/export operations should share the domain implementation where feasible.
4. Prove discovery/schema and genuine live, source stdio and packaged stdio execution. Test identical display labels/GlobalIds in separate editors, source switching during a multi-step request, read-only/denied-root/overwrite/invalid-input refusals with byte equality, Undo/Redo/reopen, and independently validated actual IFC/CSV/vector-PDF/page bounds. Verify exact loaded/package module hashes. Do not configure a persistent user client.

Exclude F08 joins, curves/roofs/profiles, driving dimensions, semantic takeoff expansion and default-layout changes. PM acceptance remains blocked until meaningful documentation/reference/export coverage is implemented, registered and transport tested on an approved integrated build; this proposal does not close the gate.
