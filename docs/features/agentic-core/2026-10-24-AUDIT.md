# Agent-access audit — October 24, 2026

## Conclusion

**New features are not automatically available through MCP.** Basic transport/model tools work, but fork-added materials, assemblies, references and documentation have semantic tool gaps. Internal functions and workspace commands do not automatically register MCP tools.

Audited main: `3e42c21e33e642d1e07bea2fc3356344f91db00e`. `app/agents.js`, `app/bim-agent.js`, the headless registry and stdio server are also byte-identical in the inspected F28-C checkout; that draft does not close these gaps. Headless tools.mjs conditionally loads BimCraft; an unavailable/old build can list no model tools. Check discovery on the actual built/installed surface. Validate the fork's packed module closure and shipped version when extending tools.

2. Reference dimensions and view/source settings with stable IDs and version diagnostics.
3. Schedules, sheets and CSV/vector PDF through existing writers, with live/headless/package parity and an agent-driven end-to-end drawing workflow.

These slices are planned, not delivered. [AGENTIC-CORE.md](../../AGENTIC-CORE.md) defines acceptance. No feature merge, deployment or MCP client setup occurred.
